# Технический паспорт монеты: IRON

- **Тикер(ы):** IRON
- **Официальное название проекта:** Iron Fish
- **Официальный сайт:** https://ironfish.network
- **Официальный репозиторий:** https://github.com/iron-fish/ironfish

- **Официальная документация:**
  https://ironfish.network/developers/documentation
- **Статус исследования:** завершено

## Идентификация сети

- **Mainnet:** запуск 20.04.2023; network ID 1; блок 60 с; генезисная
  эмиссия 42 000 000 IRON. PoW: FishHash (GPU) с блока 503338 (апрель
  2024); до этого — первичная CPU-фаза (детали алгоритма в рамках
  исследования не проверены).
- **⚠️ Сеть фактически мертва (на ноябрь 2026):**
  - 20.04.2026 — фонд Iron Fish объявил maintenance mode: команда
    разработки перешла к Coinbase/Base (март 2025), фондная
    инфраструктура (bootstrap-ноды, эксплорер, сайт) — в минимальном
    режиме;
  - 30.10.2026 — фонд объявил о полном прекращении ВСЕЙ поддержки сети:
    обнаружен consensus-level inflation bug в реализации Merkle-дерева
    (коммит начала 2019): из-за нюансов расчёта nullifier атакующий мог
    тратить одну и ту же note многократно; инфляция выведена через мост
    ChainPort ($wIRON на Base — обеспечение скомпрометировано);
  - патч (PR #5762 + postmortem «merkle-note-position-alias»)
    применим ТОЛЬКО к новой цепи с новым генезисом: несовместим с
    существующей историей mainnet/testnet; процедуры миграции и
    восстановления балансов не существует; репозиторий закрывается и
    архивируется;
  - 10.11.2026 — делистинг IRON на Kryptex.
- **Testnet:** существовал (фосет на сайте); патч несовместим и с ним.
- **Проверка идентичности:** тикер IRON в списке активов = Iron Fish
  (подтверждено исследованием: официальный сайт ironfish.network,
  репозиторий iron-fish/ironfish). Тикер исторически конфликтует с другими
  проектами «IRON» (IRON Finance и др.) — в контексте списка активов VEYRO
  идентичность Iron Fish подтверждена.

## Криптография и ключи

- **Формат адреса:** 64 hex-символа (transmission key pk = «public
  address»). Bech32 для публичных адресов НЕ внедрялся: issue #3030
  (предложение «iron1…/ore1…») закрыт через PR #3213, но #3213 реализовал
  bech32 только для экспорта/импорта аккаунтов. Префиксы «iron1/ore1»
  никогда не существовали.
- **Формат публичного ключа:** transmission key (pk) — производная от
  spending-ключей; модель Sapling-подобная (whitepaper).
- **Формат приватного ключа:** spending key (sk) — 256-битный случайный
  ключ; экспорт AccountFormat «SpendingKey» — hex-строка. Экспорт
  аккаунта: bech32-строка с префиксом `ifaccount` (текущие доки; в более
  ранних версиях — `ironfishaccount…`), JSON, Base64Json.
- **Модель ключей (whitepaper, проверено):** sk → ask/ak (трата),
  nsk/nk (nullifier), ovk (исходящие), ivk (входящие), pk (адрес).
  Формулы: ask = blake2b(sk‖0, «Iron Fish Money », 512 бит) mod r;
  ak = ask·SPENDING_KEY_GENERATOR; nsk = blake2b(sk‖1, …) mod r
  (кривая Jubjub).
- **Мнемонический стандарт:** 24 слова, кодирующие сам spending key
  (официальные RPC-доки: «The private key encoded as 24 word BIP39
  mnemonic phrase», несколько языков). Это кодировка ключа, а не BIP39-
  деривация: фраза = полный доступ.
- **Watch-only:** view key полный (видит и входящие, и исходящие) —
  `ironfish wallet:export --viewonly`; view-only аккаунт не может тратить.
  Поддержано офлайн-подписание (raw transaction + постинг spending-нодой).
- **Алгоритм подписи:** Jubjub/RedJubjub + zk-доказательства
  (Sapling-производная модель). Аппаратные кошельки: Ledger-приложение
  существовало.

## Транзакции

- **Структура:** notes + nullifiers, зашифрованные суммы (Sapling-подобная
  модель). **Критический баг (в проде с 2023):** aliasing позиций в
  Merkle-дереве → разные nullifier для одной note → многократная трата
  одной note (эксплуатировано в октябре 2026).
- **Расчёт комиссии:** модель НЕ ЗАФИКСИРОВАНА в рамках исследования.
- **Блокировки/имматурность:** НЕ ЗАФИКСИРОВАНО.
- **Модель баланса:** notes (shielded, account-based).
- **Особые поля:** memo (`ironfish wallet:send --memo`).

## Доступ к сети

- **Методы RPC:** TCP/TLS/IPC/HTTP через SDK: node/getStatus, chain/*,
  wallet/create, wallet/exportAccount (форматы: bech32/JSON/Base64Json/
  Mnemonic/SpendingKey), wallet/importAccount (с createdAt — высотой
  начала скана) и др.
- **P2P-протокол:** собственный (TypeScript-нода); детали НЕ ЗАФИКСИРОВАНЫ.
- **Лёгкий клиент:** standalone-кошелёк (ironfishw) подключался к удалённой
  ноде по TCP.
- **Узел:** TypeScript-нода (npm `@ironfish/sdk`), крипто-ядро в Rust
  (ironfish-rust). После 30.10.2026 поддержка узлов фондом прекращена;
  сеть без патча остаётся уязвимой к двойной трате note.
- **Публичные RPC:** неактуальны (сеть мертва).
- **Explorer:** эксплорер на ironfish.network — поддержка прекращена.

## SDK и библиотеки

- **Официальные SDK:** `@ironfish/sdk` (npm, TypeScript, MPL-2.0).
  MPL-2.0 допустимо как отдельный процесс/модуль, но MPL-файлы нельзя
  вливать в MIT/Apache-файлы ядра VEYRO.
- **Rust-библиотеки:** крипто-ядро ironfish-rust (в составе репозитория;
  лицензию проверить при внедрении — НЕ ПОДТВЕРЖДЕНО). Активных сторонних
  Rust SDK нет.
- **Flutter/Dart-интеграции:** официальных нет.
- **Аудиты:** внешний и внутренний аудиты покрывали поражённый код —
  inflation bug не был обнаружен при ревью (заявление фонда).

## Безопасность и ограничения

- **Известные ограничения:** consensus-level inflation bug в проде с
  2023 (код 2019); патч требует нового генезиса; существующие цепи
  (mainnet/testnet) в текущем виде невосстановимы.
- **Риски безопасности:** любой оставшийся IRON (нативный или $wIRON)
  не имеет гарантий обеспечения; транзакции в уцелевших нодах уязвимы
  к повторной трате note.
- **Блокеры:** сеть мертва — полная блокировка актива.
