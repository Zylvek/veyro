# Технический паспорт монеты: XEL

- **Тикер(ы):** XEL (XELIS). Тикер конфликтует с мёртвым Elastic (XEL) —
  идентичность подтверждена, см. ниже.
- **Официальное название проекта:** XELIS
- **Официальный сайт:** https://xelis.io
- **Официальный репозиторий:** https://github.com/xelis-project/xelis-blockchain
- **Официальная документация:** README репозитория + FAQ на xelis.io
  (отдельного doc-сайта нет; сторонний «xelis-wallet-docs» — не официален)
- **Статус исследования:** завершено

## Идентификация сети

- **Mainnet:** BlockDAG L1 на Rust; запуск mainnet — 20.04.2024. НЕ форк —
  собственный код. Версии протокола: V3 (декабрь 2025) — смарт-контракты
  (xelis-vm), сокращение блока до 5 с, переход PoW на XelisHashV2;
  V6 (июнь 2026) — текущая версия (содержание не детализировано в рамках
  исследования).
- **Параметры сети (проверены по исходникам/докам):** адреса bech32 с
  префиксом `xel:` (mainnet) / `xet:` (testnet), 63 символа; порты:
  P2P 2125, API демона 8080, API кошелька 8081.
- **Testnet:** есть (префикс `xet:`, testnet-эксплорер, фосет через
  Discord).
- **Проверка идентичности:** гипотеза матрицы «XEL = XELIS (BlockDAG,
  privacy)» подтверждена исследованием: Rust, BlockDAG, приватность
  зашифрованных балансов, mainnet 2024, репозиторий
  xelis-project/xelis-blockchain. Исторический тикер XEL у Elastic
  (мёртв) к сети отношения не имеет.

## Криптография и ключи

- **Формат адреса:** bech32, префикс `xel:` (mainnet) / `xet:` (testnet),
  63 символа. Адрес кодирует: тип (Normal = 0 / Data = 1 — с
  интегрированными данными) + сжатый PublicKey 32 Б.
- **Формат публичного ключа:** точка Ristretto255 (32 Б, compressed);
  PublicKey = PrivateKey × generator.
- **Формат приватного ключа:** 32-байтный скаляр Ristretto255.
- **Схема деривации (проверено по исходникам
  `xelis_wallet/src/mnemonics/mod.rs`):** 24 слова данных + 25-е
  слово-чексумма: CRC32 префиксов слов mod 24 — чексумма дублирует слово,
  стоящее на позиции индекса. Словарь 1626 слов на язык
  (Electrum/CryptoNote-стиль), 11 языков. Слова → тройки индексов → u32
  (little endian) → 8×4 = 32 Б = PrivateKey.
- **Мнемонический стандарт:** нативный (см. выше); НЕ BIP39 — вопреки
  сторонним заявлениям о «BIP39-совместимости» (исходниками не
  подтверждается). Фраза кодирует сам приватный ключ → восстановление =
  полный доступ.
- **Приватность балансов:** суммы зашифрованы (Twisted ElGamal на
  Ristretto255) + ZKP для консенсуса; расшифровка — только держателем
  приватного view key (FAQ: «only readable by the holder of the private
  view key»). Отправитель/получатель в транзакциях видимы — приватность
  слабее XMR/ZEC (скрыты только суммы).
- **Алгоритм подписи:** Ed25519 (стек Ristretto255).
- **Watch-only:** возможен (расшифровка зашифрованных балансов view key).

## Транзакции

- **Структура:** account-модель (не UTXO); зашифрованные балансы (Twisted
  ElGamal) + ZKP; до 255 трансферов в одной транзакции (константа
  исходников).
- **Расчёт комиссии:** 0.0001 XEL за KB + 0.00005 XEL за каждый transfer.
- **Блокировки/имматурность:** НЕ ЗАФИКСИРОВАНО в рамках исследования.
- **Модель баланса:** account-based, суммы скрыты криптографически.
- **Особые поля:** Data-адреса (интегрированные данные в адресе), burn
  (сжигание), multisig, смарт-контракты (xelis-vm, с V3), XSWD — протокол
  связи dApp ↔ кошелёк.
- **Эмиссия:** max supply 18 400 000 XEL; 8 десятичных знаков.

## Доступ к сети

- **Методы RPC:** API демона (порт 8080) и API кошелька (8081),
  WebSocket/HTTP JSON. Кошелёк может работать встроенным в ноду или
  отдельным процессом, подключаясь к удалённым нодам.
- **P2P-протокол:** порт 2125, собственный wire-протокол (Rust).
- **Лёгкий клиент:** полноценного light-протокола нет; кошелёк
  подключается к удалённым нодам. FAQ: поддержка pruning + fast sync с
  недавнего состояния цепи — балансы доступны без скачивания полной
  истории (история — отдельная операция скана).
- **Узел:** xelis-daemon (Rust); требования к диску/памяти НЕ
  ЗАФИКСИРОВАНЫ (легче классических блокчейнов за счёт pruning/fast sync).
- **Публичные RPC:** существуют (кошелёк Genesix по умолчанию предлагает
  публичные ноды); агрегаторов-списков не исследовано. Риск: узел видит
  пары отправитель→получатель (суммы скрыты криптографией).
- **Explorer:** https://explorer.xelis.io, https://testnet-explorer.xelis.io
  (транзакции/адреса видны, суммы скрыты).

    библиотека;
  - xelis-dart-sdk (MIT) — официальный Dart/Flutter SDK;
  - xelis-js-sdk (MIT) — официальный JS/TS SDK.

- **Flutter/Dart-интеграции:** xelis-dart-sdk (MIT) — готовый мост для
  Flutter-приложения VEYRO. Референсы: Genesix (Flutter + Rust через
  flutter_rust_bridge; GPL-3.0 — код заимствовать нельзя, изучать можно),
  xelis-wallet-flutter (GPL-3.0).
- **Лицензии зависимостей:** BSD-3-Clause (ядро) + MIT (SDK) — полностью
  совместимо с MIT OR Apache-2.0. GPL-компоненты — только референсные
  кошельки, не библиотеки.

## Совместимость кошелька

Реализуемость подтверждена на уровне протокола; в VEYRO ничего не
тестировалось.

- [ ] Создание кошелька — генерация ключа/seed (24+1 слово) через
      xelis-blockchain / dart-sdk
- [ ] Импорт кошелька — из фразы (= приватный ключ), из ключей
- [ ] Восстановление — из фразы; fast sync с недавнего состояния для
      балансов
- [ ] Получение — адрес `xel:…` (Normal/Data); QR (URI-схема — сверить
      при интеграции)
- [ ] Баланс — расшифровка зашифрованных балансов view key; watch-only
      возможен
- [ ] История транзакций — через wallet API (скан)
- [ ] Отправка — построение/подпись Ed25519, бродкаст через ноду
- [ ] Мониторинг подтверждений — через wallet API (BlockDAG-окончательность
      — правила подтверждения уточнить при интеграции)

### Режимы работы без серверов VEYRO (архитектурное требование)

- **Без своего сервера и без полной локальной ноды: ДА.** Кошелёк
  подключается к публичным удалённым нодам; за счёт pruning/fast sync
  балансы синхронизируются с недавнего состояния цепи без полной истории.
- **Без своего сервера, с локальной нодой: ДА.** xelis-daemon (Rust).
- **Невозможно без сервера/ноды:** ничего — серверных зависимостей нет.

## Безопасность и ограничения

- **Известные ограничения:** приватность слабее CryptoNote/Zcash — скрыты
  суммы, но граф отправитель→получатель публичен; watch-only расшифровывает
  балансы, но историю требует скана; подтверждение BlockDAG — отдельная
  механика (отличается от линейных цепей).
- **Риски безопасности:** молодая сеть (mainnet 2024) и молодой стек
  смарт-контрактов (V3, декабрь 2025); внешние аудиты НЕ ПОДТВЕРЖДЕНЫ.
- **Блокеры:** нет.

## Вывод для матрицы

- **Идентичность:** подтверждена — XEL = XELIS (гипотеза матрицы
  подтверждена).
- **Рекомендуемый статус:** из `Research required` → реализация. Полный
  цикл без серверов VEYRO; лучшие лицензии в privacy-группе (BSD-3 ядро
  + MIT dart-sdk — прямой путь во Flutter). «Full support» — после
  проверенного полного цикла в тестах.
- **Главный риск:** видимая метаданная-приватность (граф транзакций
  публичен) и молодость сети/стека.
