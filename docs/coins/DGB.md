## Идентификация сети

- **Mainnet:**
  - Genesis-хэш: `0x7497ea1b465eb39f1c8f507bc877078fe016d6fcb6dfad3a64c98dcc6e1e8496`,
    merkle root `0x72ddd9496b004221ed0557358846d9248ecd4c440ebd28ed901efc18757d0fad`
    (источник: `src/chainparams.cpp`, подтверждено в двух копиях репозитория —
    архивной `digibyte/digibyte` master и актуальной DigiByte-Core).
  - Magic bytes: `0xfac3b6da`
  - Порты: P2P `12024`, RPC `14022`
  - Блок: **15 секунд**; 5 алгоритмов PoW: SHA256d, Scrypt, Skein, Qubit,
    Odocrypt.
  - Odocrypt: активирован на блоке 9,100,000 (заменил Myr-Groestl, ~19 июля
    2019, release v7.17.2); параметры алгоритма ротируются каждые 10 дней
    (OdoShapechangeInterval) — на кошелёк не влияет.
  - Сложность: DigiShield/MultiShield (per-algo ретаргетинг) — критично для
    SPV-проверки заголовков.
- **Testnet:** magic `0xfdc8bddd`, P2P `12026`, RPC `14023`, datadir `testnet4`
  (в release notes v9.26.x упоминается как «testnet26»).
- **Regtest:** bech32 HRP `dgbrt`.
- **Проверка идентичности:** тикер однозначен. DigiByte — мульти-алго UTXO-чейн,
  работает с января 2014, непрерывно присутствует на майнинг-трекерах (WhatToMine,
  пулы) и биржах; SLIP-44 coin type 20; сайт digibyte.org официально ссылается на
  репозиторий DigiByte-Core. Genesis/magic/порты совпадают с официальными
  исходниками. Двусмысленности нет.

## Криптография и ключи

- **Формат адреса:** Bitcoin-совместимые:
  - P2PKH base58, префиксный байт `30` → адреса `D...`
  - P2SH base58, префикс `63` → адреса `S...` (текущий формат);
    легаси-префикс `5` → адреса `3...` (Bitcoin-совместимый формат старых
    кошельков; подтверждено независимо: сторонний dgb-wallet-стек обрабатывает
    «current DGB format (S…) and legacy Bitcoin-compatible P2SH (3…)»)
  - SegWit bech32: HRP `dgb` → `dgb1...` (mainnet), `dgbt` (testnet)
  - Taproot bech32m (`dgb1p...`): ядро v8.26+ (база Bitcoin Core 26) содержит
    Taproot/Schnorr; фактическое использование кошельками —
    `НЕ ПОДТВЕРЖДЕНО`
- **Формат публичного ключа:** SEC1 secp256k1 (как Bitcoin)
- **Формат приватного ключа:** WIF, префикс `128` (как BTC); **легаси WIF
  префикс `158`** (кошельки эпохи 2014; импорт поддерживается ядром — см.
  release notes 6.16.3/6.16.4 «Fixes import issue with old private keys from
  2014 era wallets»)
- **Схема деривации ключей:** BIP32/BIP44, SLIP-44 coin type **20**. Стандартные
  пути: `m/44'/20'/a'/c/i` (legacy), `m/49'/20'/...` (P2SH-SegWit),
  `m/84'/20'/...` (bech32). BIP86 (`m/86'/20'/...`) — ядром поддерживается,
  стандартное использование кошельками `НЕ ПОДТВЕРЖДЕНО`.
- **Мнемонический стандарт:** BIP39
- **Алгоритм подписи:** ECDSA secp256k1; Schnorr (BIP340) для Taproot-выходов
  (v8.26+/v9.x)
- **Совместимость восстановления из фразы:** одна BIP39-фраза восстанавливает
  все семейства адресов при сканировании путей 44/49/84/86. ВАЖНО для
  recovery-сканирования: учитывать **оба** P2SH-варианта (`S...`, префикс 63, и
  `3...`, префикс 5) и оба WIF-префикса (128/158).

## Транзакции

- **Структура транзакции:** Bitcoin-совместимая UTXO (база Bitcoin Core 26.2 в
  линейке v9): те же поля, SegWit witness.
- **Расчёт комиссии:** sat/vByte, weight-модель Bitcoin (witness discount 4).
- **Блокировки/имматурность:** coinbase maturity — 100 блоков (стандарт
  Bitcoin-форков); `НЕ ПОДТВЕРЖДЕНО` прямым чтением `consensus.h` DGB — сверить
  при реализации. Для получателя майнинговых выплат некритично (coinbase
  тратит пул), но влияет на отображение «подтверждённости» выплаты.
- **Модель баланса:** UTXO.
- **Особые поля:**
  - **DigiDollar** — нативный стейблкоин, активирован BIP9-голосованием,
    блок 23,869,440 (**17.07.2026**), «buried» с v9.26.5. Адреса DD/TD/RD; RPC
    `validateddaddress` (вместо `validateaddress` для DD), метод
    `importdigidollaraddress` — no-op в v9.26.7. «Thaw Day» — **1 ноября 2026,
    блок 24,490,000**: стартуют новые блок-правила DigiDollar (ценовая проверка
    вместо моратория минта). Базовые DGB-переводы не затронуты, но формы RPC
    (`getdeploymentinfo`, `getdigidollardeploymentinfo`) менялись между
    версиями — парсеры не должны жёстко зависеть от старых форм.
  - Payment ID/memo — отсутствуют.

## Доступ к сети

- **Методы RPC:** стандартный набор Bitcoin Core (`getblockchaininfo`,
  `getblock`, `getblockheader`, `getrawtransaction`, `gettxout`,
  `getrawmempool`, `estimatesmartfee`, `sendrawtransaction`,
  `scantxoutset`, `getaddressinfo`, …) + DGB-специфика (5 алго-сложностей в
  `getblockchaininfo`, DigiDollar-методы). Порт `14022`.
- **P2P-протокол:** порт `12024`, wire-протокол Bitcoin-совместимый
  (magic `0xfac3b6da`), версия узла — Core-производная.
- **Лёгкий клиент:** официального SPV/Electrum-клиента **нет**. Существуют:
  (а) community-публичные Electrum-DGB-серверы (список ведёт сторонний проект
  dgb-wallet; доступность нестабильна, не аффилированы с DigiByte);
  (б) BIP37 bloom-фильтры — опция узла, унаследованная от Core;
  (в) BIP157/158 в Core-линии отсутствует (сторонний dgb-wallet заявляет
  P2P BIP157/158-клиент — `НЕ ПОДТВЕРЖДЕНО`, требует проверки).
  Стратегия VEYRO: primary — RPC пользовательского узла; опционально —
  community Electrum-DGB с шифрованием и распределением запросов.
- **Узел:** DigiByte Core **v9.26.7** (06.10.2026, latest; v9 = Bitcoin Core
  26.2 + DigiDollar). Требования к диску для полной цепи —
  `НЕ ПОДТВЕРЖДЕНО` (порядка десятков ГБ); pruning поддерживается
  (v9.26.4+, `prune=N` в MiB, минимум 550).
- **Публичные RPC:** официальных публичных RPC нет (`НЕ ПОДТВЕРЖДЕНО`
  наличие стабильных). Приватность: community Electrum-серверы видят
  запрашиваемые адреса — распределять запросы, не доверять одному серверу.
- **Explorer:** канонический официальный explorer `НЕ ПОДТВЕРЖДЁН` — для ссылок
  из истории транзакций выбрать и зафиксировать community-решение при
  реализации (отдельное решение для UI).

## SDK и библиотеки

- **Официальные SDK:** DigiByte Core (C++, RPC/REST), DigiWallet iOS
  (DigiByte-Core/digibytewallet-ios, Swift). Официальных JS/TS или мобильных
  SDK `НЕ ПОДТВЕРЖДЕНО`.
- **Rust-библиотеки:** зрелого DGB-крейта не найдено. Рекомендуемый путь:
  `rust-bitcoin` (MIT OR Apache-2.0) + кастомные network-параметры (base58
  префиксы 30/63/5, WIF 128/158, HRP `dgb`/`dgbt`) + собственная валидация
  DigiShield/MultiShield-ретаргетинга для SPV-цепочки заголовков.
  PoW-алгоритмы (Odocrypt и др.) кошельку не нужны (нужны только майнеру и
  полной валидации блоков).
- **Flutter/Dart-интеграции:** готового пакета не найдено
  (`НЕ ПОДТВЕРЖДЕНО`); интеграция через FFI к Rust-ядру VEYRO.
- **Лицензии зависимостей:** DigiByte Core — MIT; rust-bitcoin —
  MIT OR Apache-2.0. Совместимо с ядром VEYRO.

## Безопасность и ограничения

- **Известные ограничения:**
  - Thaw Day (1 ноября 2026, блок 24,490,000): все узлы/индексеры ≥ v9.26.6
    (официальное требование команды). RPC-формы менялись между 9.26.4–9.26.7.
  - Мульти-алго difficulty (DigiShield/MultiShield) — SPV-клиент обязан
    корректно проверять ретаргетинг по алгоритмам, иначе принимает поддельные
    цепочки заголовков.
  - Odocrypt-ротация каждые 10 дней — влияет только на полную валидацию PoW.
  - Community Electrum-серверы — единая точка наблюдения; публичных
    официальных RPC нет.
- **Риски безопасности:** типичные для Bitcoin-стека; специфических инцидентов
  консенсуса в 2025–2026 не зафиксировано (в отличие от RVN/XNA).
- **Блокеры:** нет. Полный цикл реализуем без серверов VEYRO.

## Вывод для матрицы

- **Идентичность:** подтверждена (официальный репозиторий/сайт, SLIP-44 20,
  genesis/magic из исходников; два независимых источника критических
  параметров).
- **Реализуемость:** полная — через RPC пользовательского узла или
  community Electrum-DGB; все компоненты существуют.
- **Предлагаемый статус:** `Research required` → после полного тестового цикла
  (создание → адрес → баланс → история → отправка → бродкаст →
  восстановление) кандидат на `Full support`. До тестов статус в матрице не
  менять.
