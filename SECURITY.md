# Политика безопасности (Security Policy)

## Поддерживаемые версии

| Версия | Поддержка |
|---|---|
| 1.0.x | ✅ активная |

## Как сообщить об уязвимости

**Не публикуйте** подробности CVE в открытых issue до исправления.

1. Откройте [GitHub issue](https://github.com/Zylvek/veyro/issues) с меткой
   `[security]` — либо, для чувствительных деталей, используйте переписку
   с владельцем репозитория (профиль [Zylvek](https://github.com/Zylvek)).
2. Опишите: монету/крейт, версию, шаги воспроизведения, ожидаемое vs фактическое.
3. Ответ в течение 7 дней, оценка и срок фикса — сразу после вердикта.

## Границы ответственности (what is in scope)

- Раскрытие/подмена секретов через FFI-границу или логи.
- Обход fund-safety (chainId/genesis), TLS-политики (ssl:// / https://),
  идемпотентности broadcast.
- Подделка истории/баланса, эскалация на парольном пути (KDF/vault),
  path traversal в обработке wallet-id, инъекции Electrum/JSON-RPC.

## Не является уязвимостью (out of scope)

- Социальная инженерия на пользователе; утрата seed-фразы владельцем.
- Физическая атака на включённую разблокированную машину.
- Скомпрометированная операционная система (ключи не спасают от ключлоггера).

## Архитектурные инварианты, которые защищаются

- Секреты/сид-фразы только в Rust (Zeroizing), никогда через FFI и UI.
- TLS-only транспорт; P2P — проверка magic/genesis.
- Локальная подпись: ядро никогда не отправляет голые приватные ключи наружу.
- Восстановление только seed-фразой — отсутствие облака есть защита.

Полный технический паспорт каждой сети — [`docs/coins/`](docs/coins).
